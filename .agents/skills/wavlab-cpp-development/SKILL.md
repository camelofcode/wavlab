# WavLab C++ development

Use this skill for implementation, refactoring, review, or documentation work
in the C++ repository. For tags and GitHub Releases, use
`wavlab-cpp-release` instead.

## Preserve the architecture

- `include/wavlab/` is the supported public API. Headers are named after their
  main class, use namespace `wavlab`, and must compile when included alone.
- `src/lib/` contains private implementation and internal headers. Do not
  install or expose them to consumers.
- `src/cli/` owns CLI11 definitions, terminal formatting, file-oriented
  orchestration, and process exit status. The library must not parse arguments,
  print, or terminate the process.
- Keep `main.cpp` as the process boundary: construct, parse, dispatch, catch,
  and return. Put typed commands in the focused generator/tool/EQ/effect units.
- The reusable target is `wavlab::wavlab`; CLI11 must not propagate to it.

## Library conventions

- Target C++20 with extensions disabled. Do not raise the standard without
  satisfying the compiler policy in `docs/development.md`.
- Follow the existing class-matching `CamelCase.h` header convention and
  lower-camel-case methods.
- Prefer settings structs over long multi-parameter APIs.
- Validate complete settings and sizes before mutating samples. Preserve the
  input object when validation fails.
- Report library failures with the existing typed exception families. Include
  useful field, value, or path context.
- Treat samples as interleaved channel values and frames as complete channel
  groups. Keep this distinction explicit in names and calculations.
- Keep per-channel DSP state independent. Do not implicitly normalise effect
  output or hide clipping; integer encoding is the clipping boundary.
- Use British English for new prose and canonical C++ names. Retain documented
  American-spelling aliases where they are part of compatibility.

## CLI and documentation

- Define validation and help alongside each typed CLI11 option. Reuse
  `CliCommon.h` for shared path and open/process/save behaviour.
- A missing output path deliberately overwrites the input through
  `WavFile::save`'s failure-safe replacement.
- If command definitions change, regenerate `docs/cli.md` with:

  `./out/build/dev/wavlab _generate-cli-docs docs/cli.md`

- Keep README examples concise and keep release-facing changes in
  `CHANGELOG.md` under `Unreleased`.

## Tests and completion

- Put in-memory behaviour tests in the focused dependency-free C++ test
  executable. Use Python process tests for CLI parsing/output/files.
- Add boundary, invalid-input, unchanged-state, mono/stereo, and empty-input
  cases where meaningful. Keep fixtures small, deterministic, and generated by
  `tests/fixtures/generate_fixtures.py`.
- For an ordinary change, run the narrow affected test first, then the normal
  local gate:

  ```console
  cmake --preset dev
  cmake --build --preset dev -j2
  ctest --preset dev --output-on-failure
  cmake --build --preset dev --target format-check
  git diff --check
  ```

- Do not run every local preset by default. The required GitHub workflow owns
  GCC, Clang, Apple Clang, MSVC, shared-library, sanitizer, and Release/install
  coverage.
